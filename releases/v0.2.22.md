# ObsDog CLI v0.2.22 — candidate

This release is being qualified. Do not migrate an existing library until the
immutable CLI and matching transition assets are published together.

The candidate creates new local libraries at schema 12. Historical chunks share
their immutable revision payload and intern snapshot titles instead of storing
the same text for every snapshot. Original chunk identities, historical title
and content, frozen pages, revision history, labels, comments and pending sync
operations remain evidence, not disposable cache. Locally derived dashboard
facts are maintained from accepted retrieval and knowledge events.

Recent activity rows expose recorded opened/used counts before expansion and
identify affected Care documents, reasons and impact. Unknown historical counts
remain distinct from recorded zero. These changes do not imply improved search
relevance, answer quality or a new multilingual ranking policy.

Zero-result search rows display `0`, not `undefined`. A missing count is shown
as unknown rather than inferred from the returned results or action counts.

## Existing libraries require an explicit transition

The CLI refuses unsupported, unfenced local schemas before writable
initialization and links to the [backup-first migration guide](../guides/local-schema-migration.md).
It does not carry an indefinite historical migration chain. Installing a new
binary does not authorize data migration or stop running agents.

Separate `obsdog-migrate` tools for Apple silicon macOS and Linux x86_64 perform
only the reviewed stable 11 → 12 transition. Download the tool for your platform
from the same release and verify its manifest entry. Do not install it
permanently in PATH. Read-only check is the default; apply needs an explicit
writer pause and a new private backup bundle outside the source profile. The
tool retains consistent before/after databases and original-row fingerprints.
No library is uploaded, signed in or enrolled by that operation.

Schema numbers describe local storage, not cloud sync protocol. Connected
libraries require the compatible cloud archive reader before transition.
Recovery fences stay read-only. Other devices with separate databases need
their own local transition; no blanket process shutdown is required.

## Platforms and authentication

Linux x86_64 and Apple silicon macOS remain supported. The Linux encrypted-file
credential option introduced in v0.2.21 is retained; OS credentials are still
the default. Live Linux cloud-authentication acceptance remains a separate
check from local storage and packaging. No native macOS/iOS app is included.

## Updates and running processes

Use the current installation owner: Homebrew on macOS or `obsdog update` for
standalone installs. Pause agents that use the selected library before its
transition, reconnect client-owned MCPs afterward, and restart owned dashboards
with their previous flags. Check `obsdog_version` inside the MCP connection and
`obsdog dashboard status`; a fresh shell or browser refresh is not a restart.

Review only the ObsDog section in AGENTS.md / CLAUDE.md against the
[agent update checklist](https://github.com/obsdoghq/skills/blob/main/docs/SETUP.md#updating-cli-and-agent-guidance).
The independent plugin still provides `find`, `remember`, `maintain` and
`documentify`; no skill is added, removed or renamed here.
