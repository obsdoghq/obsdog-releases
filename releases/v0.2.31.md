# v0.2.31

Adds atomic document extraction and section insertion, document-scoped block
identities, raw Markdown output and a lightweight document revision check.
It also removes duplicate whole-library index validation from common knowledge
commands and reserves the SQLite writer before structural edits read mutable
state. Writes still publish a complete search snapshot; latency depends on the
library and concurrent writers.

Read the current document and use its exact revision for an edit. A conflict
requires rereading and reconciling the intended change.

```sh
obsdog document read --id DOC_ID --with-block-ids --format json
obsdog block list --document DOC_ID --format json
obsdog document read --id DOC_ID --format markdown
obsdog document status --id DOC_ID --since-revision REV_ID --format json
```

`document split --id DOC_ID --base-revision REV_ID --blocks ID,ID --title TITLE
--reason TEXT` reuses atomic Care extraction. Complete heading subtrees move to
a new document with lineage on both sides and preserved history. Relative-link
or reference checks can refuse extraction; do not work around a refusal by
copying and deleting content.

`document append --id DOC_ID --base-revision REV_ID --file SECTION.md --before
BLOCK_ID --reason TEXT` inserts one heading-led section atomically. The section
may contain1–20 parsed blocks. Existing block IDs, content revisions, parents
and relative order stay intact. Insertion that would reparent existing content
is refused. Multi-line bullet continuations count as separate parsed blocks;
append errors now report the actual count.

Connected insertion requires exact-Space preparation against a compatible
server advertising `document_insertion_v1`. Update all clients that use that
Space before inserting: an insertion receipt raises its writer/consumer floor,
and older clients are then refused for that Space. Other Spaces retain their
existing compatibility. An unprepared connection records no unsupported
insertion receipt or outbox operation. Compensation does not lower this floor.

`block move --ids ID,ID` moves a contiguous set of complete subtrees in one
local operation. Changing batches are currently local-only; a connected batch
that changes order is refused before mutation. Agent moves require
`--base-document-revision REV_ID`. An already-positioned move succeeds without
new revisions, history, indexing or sync operations.

Block-update errors now point to `block split` when one block must become two.
For several text corrections with the same structure, prefer one exact-base
`document update` rather than many individual block writes. The existing
verbatim block split, append identity preservation, revision conflicts and
`.md`/`.blocks.json` export pairing remain available.

This release keeps stable schema12. Installation does not migrate an older
library, enable sync, execute suggested splits or restart existing MCP/viewer
processes. Restart those owned processes after upgrading to select the new
executable. The [history retention guide](../guides/history-retention.md) and
[schema migration guide](../guides/local-schema-migration.md) still apply.
