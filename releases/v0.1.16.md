# CLI v0.1.16 — Living memory

Real use and attributed feedback now influence the next search in a bounded,
explainable way. Old activation fades without deleting documents or history.

- Default `--ranking adaptive` adjusts only the first 100 eligible lexical
  candidates, for the same query cue and exact current block revision, within
  +/-20%. `--ranking lexical` preserves the prior baseline.
- `obsdog memory show` inspects private activation, observed query/co-use links,
  attribution, selected samples and limits. It records no new observations.
- Returned results alone do not create links or positive evidence. An open
  creates a provisional cue association; actual use and explicit usefulness
  strengthen it. Two genuinely used blocks can form a co-use observation.
- One cue/block/day sample bounds repeated-call amplification. New revisions
  do not inherit old judgments. Unknown is not negative; rare knowledge remains
  searchable. Useful new use can reactivate dormant traces.
- Server v0.1.27 and web Living memory show synchronized observations separately
  from authored references. Web browsing does not fabricate use or feedback.

Existing data is preserved. No numbered migration, automatic upload, background
worker, factual ontology extraction, source deletion or native app update is
included. Exact constants are an explicit beta policy, not proven optimal
parameters; ranking efficacy is being evaluated independently. Projection
overflow/corruption falls back visibly to lexical search.

Install using the checksum-verified v0.1.16 release installer or Homebrew.
Standalone users run `obsdog update`; package-manager users use `brew upgrade`.
See the [usage guide](../guides/living-memory.md). Local use remains account-free.
