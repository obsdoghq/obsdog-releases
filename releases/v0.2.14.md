# ObsDog CLI v0.2.14

This release makes three knowledge-care follow-ups easier without changing the
default search or importing anything automatically.

- `label list` distinguishes the revision where an assignment was recorded
  from whether it applies to the current document or block. An old revision
  reference is history, not proof that a label stopped working.
- `care source list` gives a bounded, read-only worklist of recorded source
  checks and their age. It does not visit a stored path or URL, fetch a source,
  or declare old evidence fresh.
- `document append --id DOC_ID --base-revision REV_ID --file SECTION.md --reason
  TEXT` adds a heading-led section to the same document, preserving its
  existing block identities and revision history. It does not make `document
  import` an upsert. The new section is limited to 20 blocks; stale revisions
  and invalid Markdown boundaries are rejected. An unchanged appended head
  can be conditionally reverted through Care.

Local-only Spaces can use append without signing in. A connected Space needs
the server's authenticated `document_append_v1` capability and compatible
writers; the CLI refuses an unprepared append. After a Space accepts its first
append receipt, older sync clients cannot safely write or read that Space's
newer transport state and receive an upgrade-required response. No Space is
prepared, synced, or changed merely by installing v0.2.14.

After upgrading, restart a running `obsdog dashboard serve` process and
reconnect agent sessions that own an `obsdog mcp` process. Replacing the CLI
file does not replace already-running processes.
