# v0.2.29 — Bounded history and offline recovery

In a Space with history retention enabled, keep the current document version,
the latest ten versions including current, and every version superseded within
seven days. A version stays if any of these conditions applies. Twenty edits in
one day can therefore retain all twenty versions. Unchanged blocks needed by a
retained version stay readable.

Ordinary document and block links follow current content. Earlier searches,
uses, evaluations and citations keep their original revision identities. If an
old full body expires, exact reads report that it is unavailable; history keeps
its identity, hash and authorship. Expiry never substitutes current or empty text
for the requested old body.

Compatible sync pulls restore a complete checkpoint before applying later
changes. Offline edits are preserved as recovery drafts and original pending
operations. They are not acknowledged or automatically rebased. Inspect/export
the drafts and reconcile selected edits against current content before resuming
work from a fresh replica. Preserve the original profile during recovery.

Connected backup recovery now requires freshly exported retention evidence from
the current server. Restore reapplies that checkpoint and expiry ledger before
publishing the recovered Space. An old offline backup alone cannot establish
current retention policy. The recovery file contains private knowledge; obtain
it anew for each restore and keep it private.

Local cleanup remains explicit. Updating the CLI does not enable cleanup in an
unprepared local Space. Preview and Apply use a digest-bound, bounded batch;
current and retained dependencies remain protected. See the
[history and recovery guide](../guides/history-retention.md) for commands.

This release supports Apple silicon macOS and Linux x64. Existing supported local
libraries keep their stable storage baseline. The desktop app release is separate.
