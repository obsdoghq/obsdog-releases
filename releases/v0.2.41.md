# v0.2.41 — Full-history download recovery

Download complete retained histories with larger numbers of historical document
layouts. Existing activity evidence, expired-detail boundaries and private offline
recovery drafts remain intact. Installation does not migrate your library or
start a synchronization.

The CLI now distinguishes a server checkpoint that needs maintenance from an
expired sync cursor. `activity_detail_expired` means the server must refresh its
checkpoint; signing in again does not regenerate it. Preserve the local profile
and retry after server recovery. `client_upgrade_required` means the Space needs
a compatible current client before its complete history can be downloaded.

Complete checkpoint downloads have a longer default request allowance. Explicit
command deadlines and cancellation still apply. A timeout does not imply that
pairing was lost or authorize deleting local pending changes.

Update with your normal installation method, verify `obsdog version`, and retry
the original `sync pull` command. Restart a running dashboard to load the new
binary. See [history retention and recovery](../guides/history-retention.md).
