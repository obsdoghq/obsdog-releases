# v0.2.39

This release makes readiness, storage measurements and backup coverage explicit.

- space write-readiness now prints ready/status/writer in human output. Default
  exit0 still means the probe executed; explicit --require-ready returns3 for an
  inspected non-ready state. JSON reports the same result.
- Writer samples explain why transaction age can remain null: the OS lock
  inventory exposes owner/range, not acquisition time. Sample spans and process
  uptime do not prove continuous lock age.
- Compact timestamps its freelist samples and reports after_snapshot_cleanup
  separately. Freelist bytes are not a VACUUM savings or duration prediction;
  zero does not rule out unused bytes inside allocated pages.
- Optional --storage-details reports read-only table/index allocation, payload
  and unused page bytes. The default scan budget is2s; explicitly select1ms..30s
  with --storage-details-budget, within the command deadline. Check complete/status;
  partial or unavailable results are not zeros or guaranteed reclamation.
- Backup reports ZIP archive size and compressed/uncompressed SQLite entry sizes.
  The existing default copies complete retained database contents and the Space
  manifest, while omitting private drafts, profile identity and credentials.
- Explicit --include-drafts preserves both private capture/correction draft trees
  with a bounded size/hash inventory. Use an idle profile: DB and file capture is
  not a single atomic cross-file snapshot.
- Restore accepts old DB-only and new draft-bearing archives into a fresh private
  destination. Original recovery identity is retained. The default DB limit stays
  2GiB; intentionally large backups require --max-database-bytes, at most64GiB.
- dashboard status --check-notice --space SPACE_ID --port PORT exercises the same
  stale warning against one selected synthetic loopback listener. Ordinary
  automatic checks still use only the default port.

The [storage and backup guide](../guides/storage-and-backup.md) explains measurement
boundaries, archive coverage and recovery. The [accepted-work guide](../guides/accepted-work.md)
adds a bounded noninteractive holder with acquired-lock/live-child checks and
finally cleanup. Use disposable synthetic profiles for reproduction.

Local schemas, writer floors and existing retention policies are unchanged.
Do not infer a live database leak from compressed versus uncompressed sizes.
Standalone archives are supplied for Linux amd64 and macOS arm64. Additional
native macOS execution was waived; archive presence does not establish native
validation. Checksums, SPDX, licenses, notices and source revision accompany assets.
