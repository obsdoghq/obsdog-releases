# ObsDog CLI v0.2.20

The first public Linux x64 CLI release. Supported archives:

- `obsdog_v0.2.20_linux_amd64.tar.gz` — Linux x86_64.
- `obsdog_v0.2.20_darwin_arm64.tar.gz` — Apple silicon macOS.

Both are built from the same stable v0.2.19 product code. This is a packaging
and installation update, not a search-policy or storage-schema change.
Schema 11 remains unchanged; upgrading from v0.2.19 adds no new migration.
Older libraries retain the existing [backup-first migration guidance](../guides/local-schema-migration.md).
Installing or upgrading does not sign in, enable sync or upload knowledge.

The standalone installer selects the correct OS/CPU, verifies the archive's
SHA-256 and runtime version, and replaces only its owned executable. It accepts
`sha256sum` or `shasum -a 256`. Each platform has a packaged-binary SPDX SBOM;
`checksums.txt` covers both archives, both SBOMs, the installer, binary license,
third-party notices and `REVISION` source identifier. Earlier releases remain
unchanged. Linux ARM64, Intel macOS and Windows are not supported by this release.

Local Personal, search, stdio MCP and the loopback dashboard need no account or
graphical desktop. Cloud login on Linux requires an unlocked Secret Service
keyring over D-Bus. Headless local use does not require that service; credentials
never fall back to plaintext. Linux cloud-login acceptance is separate from the
local-only packaging checks.

The CLI and AI plugin are installed separately under one setup command:

```sh
curl -fsSL https://obsdog.ai/install.sh | sh -s -- --client codex
obsdog version
obsdog document list
obsdog dashboard serve
```

Use `--client claude` for Claude Code. The chosen agent CLI must already be
installed. The helper reuses a compatible CLI or installs via Homebrew on macOS
and the standalone path on Linux. Setup creates no sample knowledge and does
not rewrite AGENTS.md / CLAUDE.md. The four skills remain `find`, `remember`,
`maintain` and `documentify`; no skill was added, removed or renamed for this release.

After upgrading, stop and rerun owned dashboard processes with the same
Space/port flags. Reconnect host-owned MCP sessions so they load the new binary.
Use `obsdog dashboard status` and `obsdog_version` inside the existing MCP
connection to verify the running version; a fresh shell alone is not sufficient.
Follow the [agent update checklist](https://github.com/obsdoghq/skills/blob/main/docs/SETUP.md#updating-cli-and-agent-guidance)
to review the ObsDog section of personal instructions without overwriting other rules.

The macOS desktop and iOS apps are not part of this CLI release.
