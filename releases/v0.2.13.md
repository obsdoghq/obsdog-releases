# ObsDog CLI v0.2.13

This patch separates two Markdown diagnostics that looked alike. `obsdog
doctor` now labels an older paragraph's trailing-newline normalization
separately from a structural block mismatch. A valid `block split` or `block
merge` can edit another block without rewriting that older paragraph; newly
created blocks still have to match their parsed type, depth, parent and text.
No document is repaired or changed by running `doctor` or installing the CLI.

Exact duplicate candidates remain inspectable, including retired history.
`doctor` now marks a group historical-only when fewer than two documents in
it are visible in default search. A candidate group is never an automatic
merge or a claim that a new import occurred.

`trace list` shows recorded lexical-pool and frozen-window candidate counts
without running a new search. New zero-hit runs explicitly record zero
candidates; a count missing from an older run remains unknown in the list.
The frozen 100-result window is not a count of every match in the library.
For a single long Korean compound that has no exact hit, search may suggest
up to two shorter-prefix document hints. Hints stay in the selected Space and
visibility/filter boundary, and are not hits or proof that the full term is
documented. Normal search ranking is unchanged.

After upgrading, restart a running `obsdog dashboard serve` process and
reconnect agent sessions that own an `obsdog mcp` process. Updating the CLI
file does not replace already-running processes. Local-only Spaces remain
local-only; installation does not sign in, sync or upload knowledge.
