# ObsDog CLI v0.2.10

This release lets you correct an existing document without creating a second
document by accident. `document update` replaces Markdown only when the exact
document revision is still current and its block structure is unchanged.
`document rename` changes the stored title independently of its first heading.
Both retain the document identity and revision history. For a reviewed duplicate,
`document supersede` retires that source in favor of a named canonical document
without copying its blocks into the canonical one. It is recoverable; it is not
a hard delete or an automatic duplicate cleanup.

`obsdog doctor` continues to show exact duplicate candidates, including
deprecated ones, but now explains each document's original creation time,
update time and active versus default-visible block counts. A candidate group
alone does not prove a new import. It does not remove history or silently
decide which document is canonical.

Concurrent writers now use a bounded local write reservation. If another
writer changes the base revision first, the later operation reports a conflict
instead of silently overwriting it. If the database stays busy beyond the
bound, the command fails without a partial knowledge change.

For a Space already connected to ObsDog sync, full-document update and
supersession require a compatible server and an explicit fresh
`obsdog sync prepare-care` check for that exact Space. Without that check, the
new action is deferred before a receipt is queued. After a new-action receipt
is accepted, older clients that cannot read it receive an upgrade-required
response on that Space. Ordinary local-only use needs no account or server.

After upgrading, restart long-running `obsdog mcp` and `obsdog dashboard serve`
processes. An existing agent session or browser refresh alone continues using
the old process. No document is edited, retired, synced or uploaded by merely
installing this release.
