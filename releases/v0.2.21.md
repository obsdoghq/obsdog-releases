# ObsDog CLI v0.2.21

Linux x64 gains an explicitly selected encrypted-file credential store for
environments without a desktop Secret Service keyring. The OS credential store
remains the default. There is no automatic fallback or plaintext token file.

The operator independently supplies one random 32-byte base64 unlock key through
a trusted environment or existing private file. Human browser approval, exact
server/Space/device/scopes, refresh rotation and logout revocation are unchanged.
ObsDog does not generate keys, migrate credentials or issue service accounts.
See [Linux cloud-login setup and recovery](../guides/linux-cloud-login.md).

Supported archives remain Linux x86_64 (`linux_amd64`) and Apple silicon macOS
(`darwin_arm64`). This patch changes credential custody, not search policy,
knowledge history, schema or graph behavior. Schema 11 is unchanged; upgrading
from v0.2.19 or v0.2.20 adds no migration. Installing/updating does not sign in,
enable sync or upload data. Older incompatible libraries follow the existing
[backup-first migration guide](../guides/local-schema-migration.md).

Each platform has a packaged-binary SPDX SBOM. The shared checksum manifest
binds both archives/SBOMs, installer, binary license, third-party notices and
the exact source revision. Previously published versions remain unchanged.
The native macOS/iOS apps and other CPU/OS targets are not part of this release.

## Validation scope

Automated security/credential-store tests and native packaged local-only
workflows have passed. Existing schema-11 history is preserved by retained-data
checks. A live browser-approved Linux cloud login, rotating refresh and server-
revoking logout have not yet completed manual acceptance for this release.
These packaging checks do not certify that end-to-end cloud-authentication flow.
Follow the Linux setup guide and verify it in your own environment before relying
on connected operations; local-only workflows do not require that validation.

## Installation and agent update

```sh
curl -fsSL https://obsdog.ai/install.sh | sh -s -- --client codex
obsdog version
```

Use `--client claude` for Claude Code. Existing Homebrew installs update with
`brew upgrade obsdoghq/tap/obsdog`; standalone installs use `obsdog update`.
Do not switch installation owners just to upgrade.

Stop and rerun owned dashboards with the same Space/port flags, then reconnect
host-owned MCP sessions. Verify `obsdog dashboard status` and `obsdog_version`
inside the existing MCP connection; a fresh shell alone cannot identify it.
Follow the [agent update checklist](https://github.com/obsdoghq/skills/blob/main/docs/SETUP.md#updating-cli-and-agent-guidance)
to review only the ObsDog section in AGENTS.md / CLAUDE.md without overwriting
other instructions.

## Skills

The plugin version is independent of the CLI. `find`, `remember`, `maintain`
and `documentify` remain unchanged; no skill is added, removed or renamed by
this credential patch. Local knowledge workflows still need no cloud account.
