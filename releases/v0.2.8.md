# ObsDog CLI v0.2.8

This release makes duplicate imports and retired knowledge easier to handle
without rewriting or deleting a Space's history.

`document import` creates a new document; it never updates one by title or by
round-tripping `document read` through a temporary file. By default, an import
now refuses an existing document in the selected Space with the same nonempty
source path or identical current Markdown, and shows the existing document ID.
Use `--fork` only when a separate copy is intentional. A changed source file is
not an automatic update: inspect the existing document, then use revision-checked
block updates or a reviewed care plan. `obsdog doctor` reports bounded exact
duplicate candidates for inspection; it does not merge them automatically.

New searches consider active document labels as well as block labels. A
`lifecycle:state=deprecated` label at either level hides the affected knowledge
by default. Use `--include-deprecated` to inspect retired material, including
with an explicit label filter. Earlier search runs and their recorded results
remain intact; later label changes do not rewrite their traces. Protected label
definitions and superseded assignments are clearer in human output.

`document read --format human` emits the full Markdown without intentional
truncation. Its rendered H1 can differ from the document's stored title; use
`--format json` or `--structure` when identity or revisions matter. Do not infer
that importing the output updates the original document.

No existing document is automatically retired, merged or removed by this
upgrade. Search visibility changes only for items already carrying an active
deprecated label. Keep a recoverable backup before a major library change, and
review suspected duplicate groups before making care edits.
