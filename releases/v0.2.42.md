# v0.2.42 — Account connections and independent Space grants

Connect your device to your account without choosing a local Space or copying
an ID before login. In the browser, review the account and device and choose
account connection only or an eligible Space. Add another Space later with
`obsdog auth grant`; switching among approved Spaces needs no new pairing.

Use `auth accounts` and `auth use --account ACCOUNT_ID` to manage explicit
account selection. `auth revoke-space --space SPACE_ID` removes one grant;
`auth logout` disconnects that account's device and grants. Neither deletes
local knowledge. Failed revocation retains the local credential until confirmed.

Credentials remain in the configured secure store. Interrupted record updates
can recover on the next operation; timeouts do not erase unrelated accounts.
Linux without Secret Service still requires explicit encrypted-file setup and
an independently provisioned key. There is no plaintext fallback.

Existing exact-Space credentials and local libraries are preserved. Login never
starts sync, uploads knowledge or replaces your default Space. First pull still
requires its own explicit command. This release includes v0.2.41 full-history
checkpoint recovery.

Update using your installation method and verify `obsdog version`. Follow the
[headless cloud login guide](../guides/linux-cloud-login.md), and use the exact
verification URL printed by the new CLI. The hosted MCP plugin has a separate
connection; CLI login does not reauthenticate it.
