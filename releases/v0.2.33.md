# v0.2.33

New local libraries share unchanged immutable membership pages and block state
across search snapshots, including snapshots retained by retrieval runs. Existing
chunk identities, historical revisions, labels and frozen pages stay exact.
Learned projection reuses unchanged per-run sample derivation while recomputing
current eligibility, as-of filtering, daily winners and decay. Scoring policy and
logical sync payloads are unchanged.

Existing schema12 libraries remain readable and writable without migration.
Fresh libraries use13. The optional, separately checksummed
`obsdog-share-migrate` performs exact12→13 with paused writers, private consistent
before/after backups, original-row fingerprints and integrity checks. The
existing11→12 helper keeps its original meaning. Read the
[version-specific migration and recovery guide](../guides/local-schema-migration.md)
before changing a library. Older writers refuse13; a separate device may retain
its supported12 library and logical sync, subject to existing consumer floors.
Schema13 history adoption requires a receiver advertising
`personal_history_schema13_v1` before import.

Sharing reduces repeated metadata for newly captured snapshots. Existing dense
history is retained, and source validation still scales with current library
size. Command latency can increase. This release does not shrink an existing DB
file, run VACUUM automatically or promise faster writes or smaller WAL files.
Passive learned-projection reads do not write sample templates. Ordinary admitted
opens may warm bounded caches. Cache misses use canonical events or an explicit
unavailable result.

Installation does not sign in, upload knowledge, migrate an existing library,
execute proposed document splits or restart owned MCP/viewer processes. The
[atomic authoring commands](v0.2.31.md),
[current text reuse and prepared connected batches](v0.2.32.md), and
[retention recovery boundaries](../guides/history-retention.md) remain available.
