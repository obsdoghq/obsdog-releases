# CLI v0.2.4 — bounded care with exact history

Apple silicon macOS CLI, stable channel. No account is required for local use.
This is not a macOS desktop application or an iOS release.

## Added

- `care check`, `apply`, `defer`, `runs` and `revert` for bounded, evidence-backed
  exact-revision plans. Outcomes distinguish applied, deferred, failed and
  compensating reversals; no edit count is labeled a quality improvement.
- Block update/split/merge and same-Space document extraction/merge, preserving
  source history, predecessor/successor lineage and exact-revision judgments.
- One complete multi-document sync operation after authenticated
  `sync prepare-care` on an existing connection. Stale plans cannot partially
  update a document; incompatible writers are refused rather than downgraded.
- Conditional recovery that appends history and preserves later authors.
  Replaying a reverted request does not reapply it.
- Read-only outcome windows in insights and the local dashboard.

## Boundaries

Read the [AI care guide](../guides/ai-care.md) before use. Plans cover at most two
documents and 200 active blocks per document; unsupported references or
incompatible state defer instead of stripping evidence. Care is active-task work,
not a background agent, semantic truth verifier or automatic whole-library cleanup.
It neither enables cloud sync nor authorizes private-source upload.

Connected care requires server v0.1.29+ and compatible active clients. After care
history is accepted, older writers cannot safely write that Space. Local commit
and server acceptance remain separate outcomes. A local-only restructured library
cannot use history-unaware enrollment; use a retained-data backup for recovery,
not an export/import shortcut that discards exact identities.

## Verification

Stable numbered migrations remain 1–10. Regression/race/vet, all five action and
reversal cases, producer/server/cold-replica conformance, stale writers, injected
failure rollback and exact backup recovery pass on synthetic data. Packaging
checks verify the single-file archive, notices, SPDX inventory and checksums.
These checks do not establish retrieval gains or real-user acceptance.

Use one installation owner: `brew upgrade obsdoghq/tap/obsdog`, or standalone
`obsdog update`. Update the independently installed AI plugin as well; plugin
v0.3.5 provides the matching guidance for Codex and Claude Code.
