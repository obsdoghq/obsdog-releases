# v0.2.30

Fixes cold recovery when a library already has built-in label definitions. Matching
label semantics are accepted even when their local creation time or description
differs. Conflicting definitions still stop recovery.

Also fixes nullable comment metadata during checkpoint installation. Early history
whose original search details were never stored stays explicitly partial, with
its original evaluations and reference identities preserved. Recovery
remains atomic: a failed validation preserves the existing library and pending
work. This release keeps the stable schema12 format.

The [history retention guide](../guides/history-retention.md) describes current
links, exact historical observations, expired bodies and offline recovery.
