# ObsDog CLI v0.2.7

This maintenance release fixes the local dashboard upgrade lifecycle. A CLI
update changes the executable on disk but cannot replace a dashboard process
that is already running. The previous process can otherwise keep serving old
UI and API assets after the browser reloads.

From v0.2.7, the dashboard checks whether its executable or its invoked
Homebrew link changed. It displays a restart notice when opened or revisited.
Starting `obsdog dashboard serve` again on a port held by an older version of
the same Space now explains the collision instead of reusing that server.
Standalone `obsdog update` includes the conditional restart instruction;
Homebrew installations remain owned by `brew upgrade obsdoghq/tap/obsdog`.

After upgrading, stop the old foreground dashboard, run
`obsdog dashboard serve` again (with any previous `--space` and `--port`
flags), then refresh the browser. Refreshing alone cannot replace the process.
No process is terminated automatically, and this check does not upload Space
data. A dashboard started on v0.2.6 or older needs this one restart before it
can detect future binary changes.
