# v0.2.43 — Reliable history block restoration

Fix a first-download failure reported as `UNIQUE constraint failed:
blocks.document_id, blocks.ordinal`. Some valid histories contain both current
and retired blocks whose arrival order caused a local position conflict.

History restoration now keeps retired blocks separate from current positions
while preserving their original history and the current document order. Repeated
downloads retain the same identities and contents. Failed restoration still
rolls back atomically.

Update using your installation method, verify `obsdog version` reports v0.2.43,
and retry the same `sync pull` command. Keep your existing Space and account
connection; this fix does not require re-pairing, database reset or uploading
local knowledge. It includes the earlier account connection and large-history
recovery improvements.

See [history download and recovery](../guides/history-retention.md).
