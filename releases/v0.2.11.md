# ObsDog CLI v0.2.11

This release makes retrieval misses easier to inspect without reading the
underlying database. `obsdog trace list` shows bounded, newest-first run IDs
with optional zero-result, time and actor filters. It does not print query text;
`trace show --run` opens one selected trace. New runs record their versioned
search policy, while older runs remain `unknown` instead of being silently
classified under the current algorithm.

`obsdog trace recovery --miss ID --rehit ID --rank N` compares an existing
zero-result run with a later run of the exact same query. It distinguishes a
current returned candidate, a re-hit that the follow-up actor actually used,
and a stale block revision. It creates no search, feedback or quality rating.
A re-hit does not prove the original miss was a knowledge gap or that the
answer was useful.

A zero-result search for one code-style identifier may show up to three
adjacent-topic document hints from the same Space and visibility filter.
These are navigation suggestions, not ranked hits or proof that the exact
identifier exists. They do not count as opened or used knowledge.

No account, sync, document migration or background process is enabled by
installing this update. After upgrading, restart any running `obsdog mcp`
and `obsdog dashboard serve` processes; an existing agent session or browser
refresh keeps using the old process.
