# v0.2.32

Writes reuse unchanged current search text instead of reindexing every block.
Search still returns exact immutable current chunks, and past results keep their
original revisions and labels. Complete snapshot membership and source checks
still scale with library size; concurrent writers and storage affect latency.
The extra lookup index also consumes space. This is not a constant-time edit or
a promise that every library writes at the same speed.

`block move --ids ID,ID --before ANCHOR --base-document-revision REV --reason TEXT`
also supports connected Spaces prepared against a server advertising
`document_reorder_v1`. Read current IDs and revisions first. Select complete,
disjoint subtrees in source order, with an anchor outside them; `--after` places
the selection after the anchor's complete subtree. Existing Markdown parents,
block IDs, content revisions and relative order within each retained group stay
intact. Existing Care bounds allow 2–200 roots and at most 200 blocks in the
complete document frame. Read the Care receipt and document after success.

Update every active client for that Space before the first connected batch.
Its receipt raises the Space's consumer/writer floor; older clients are refused
for that Space, and compensation does not lower the floor. Other Spaces retain
their prior admission. Verify the exact endpoint/Space with `sync prepare-care`;
an unavailable capability refuses a changing batch without queuing an unsupported
receipt or operation. Installation alone does not enable this server capability.
Adoption includes a supported request's recorded deferred/failed receipt, because
older consumers cannot decode that new history either. A read-only `care check`,
an unsupported refusal or a no-op records no receipt and raises no floor.

An exact-base move already in position succeeds without new history or indexing.
Repeating the same explicit command after a lost response returns its original
receipt even if another writer later edits a root. A new stale intent is refused.
Keep the original base/reason/actor for a retry, then read the current document
before deciding on a different action. Never copy and delete blocks to bypass a
structural or reference refusal.

This release keeps schema12 and canonical historical membership. Before batch
adoption, older stable clients can reconstruct their supported search cache from
that membership; new readers also accept the legacy cache. This compatibility
does not override the structural writer/consumer floor after adoption.

Existing atomic document extraction, positioned append, scoped block IDs, raw
Markdown and revision-status commands remain available. Installation does not
edit company documents, execute proposed splits, migrate an older library or
restart MCP/viewer processes. Restart those owned processes to select the new
executable. The [retention](../guides/history-retention.md) and
[schema migration](../guides/local-schema-migration.md) guides still apply.
