# ObsDog CLI v0.2.27

This patch fixes an existing-history transfer failure in current schema-12
libraries. The source write fence now protects the physical chunk records behind
the logical history view. Retained content and revision history stay unchanged.

It also fixes retrying the exact committed transfer plan after reopening its
read-only source. The retry reads the existing receipt without trying another
write. A different plan or changed source still fails safely. New source fences
retain the writer lock, complete fingerprint checks and atomic rollback.

Use the same saved plan when retrying an interrupted transfer. Do not remove a
source fence or create a different plan to bypass an error. Review
`obsdog sync --help` before the explicit `sync adopt-preview` / `sync adopt`
workflow; installation does not transfer or merge any library.

Schema 12, remote evidence compatibility, ranking and local-only use remain
unchanged. Already-transitioned schema-12 libraries need no repeat migration.
Schema-11 libraries still need the separate, backup-first
[11 → 12 transition](../guides/local-schema-migration.md).

Apple silicon macOS and Linux x86_64 remain supported. The checksum manifest
covers both CLI archives, separate transition tools, SPDX inventories, installer
and license notices. Updating does not sign in, grant permissions, enable sync
or update a desktop app.

Run `obsdog update` for a standalone installation or
`brew upgrade obsdoghq/tap/obsdog` for a Homebrew installation. Restart your
client-owned MCP and dashboard processes to use the new executable.
