# v0.2.36

This release separates available knowledge from observation persistence and makes structural diagnostics repairable.

- Ordinary read/write access no longer performs snapshot cleanup. Search/open bound observation admission separately, return actual content and exact next-read targets on known prewrite refusal, and distinguish not_recorded from an unknown commit outcome. No synthetic run/hit/event or use is recorded for diagnostic fallback.
- Each SQLite reservation attempt respects its remaining admission allowance. Each long-lived stdio MCP request gets a fresh allowance. Success/failure diagnostics expose operation, phase, attempts, elapsed time and actual sampled WAL owner when available. Missing owner/transaction age has an explicit reason; sample span is not continuous lock age. Progress goes to stderr and protocol stdout stays clean.
- Local MCP errors include a structured error_code, message and diagnostics and omit the normal success result. An error must not be interpreted as no matching knowledge.
- Doctor distinguishes affected documents, structural block mismatches, document-level boundary issues and permitted legacy newlines. Bounded scan/list completeness, totals and remaining counts are explicit. IDs, ordinals and40-character previews connect doctor and Care diagnostics. Noncontiguous extraction names the conflicting range including gaps.
- Use exact-head document repair-parent-context, with a read-only preview, to recalculate parents from unchanged ordered Markdown through existing structural Care. It preserves every block ID, content revision, kind/depth, byte and position. Other boundary mismatches are refused. Identical retries return the original receipt. Ordinary block move and document update also support read-only dry-run validation.
- Retire an exact temporary document without a replacement sink. Default lists omit retired documents; exact read/history and include-retired remain available. Retirement preserves history.
- space compact previews DB/WAL/free pages without a writer; explicit apply performs bounded eligible cleanup, atomic SQLite VACUUM and a bounded checkpoint. It preserves protected history, pins, drafts and compatibility floors. VACUUM cannot reclaim live historical rows. Preserve an accepted backup first.
- JSON capture drafts include effective title and source_path. Failed capture/ordinary maintenance exposes draft/base/original-receipt recovery state instead of inviting duplicate import.

See [local availability and maintenance](../guides/local-maintenance.md). Existing schema12 and fresh schema13 remain supported; installation does not migrate, enable a retention policy, stop a writer or reconnect an existing client. No new server action/schema/DDL is required. Check the installed CLI and loaded guidance separately; active sessions retain their old process and instructions until reconnected.

Synthetic execution and installation checks establish these contracts. They do not identify every historical contention cause or claim a particular user's latency/storage improvement. SQLite still admits one physical writer per database, while exact revision checks separately govern logical conflicts.

Standalone CLI: macOS arm64 and Linux amd64. Native desktop/mobile distribution remains separate. Binary licenses, notices, SPDX files, source revision and checksums accompany the unchanged canonical package payloads.
